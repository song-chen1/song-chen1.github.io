📦 包含内容

本仓库提供 177 个科学与研究技能，分为以下几类：

  • 100 多个科学与金融数据库：Database Lookup 技能记录了 80 个可公开访问、注册后访问或需许可访问的数据库（PubChem、ChEMBL、UniProt、COSMIC、ClinicalTrials.gov、FRED、USPTO 等），包括接口选择、分页和数据来源记录。另有专门的技能覆盖 DepMap、Imaging Data Commons、PrimeKG、NCATS ARAX、U.S. Treasury Fiscal Data、Hugging Science、OneKGPd、Genomic Intelligence 和 AlphaGenome。BioServices、Biopython、gget 等可访问多个数据库的软件包进一步扩大了覆盖面
  • 70 多个经过优化的 Python 软件包技能：为 RDKit、Scanpy、PyTorch Lightning、scikit-learn、PyTDC、PathML、pydicom、NeuroKit2、PufferLib、QuTiP、GeoPandas、pymatgen、BioPython、Qiskit、分子动力学（OpenMM/MDAnalysis）等提供明确定义、区分版本的工作流。智能体仍然可以使用任何 Python 包；这些技能只是为上述软件包提供更有力、更安全的指导
  • 9 个科学平台集成技能：为 Benchling、DNAnexus、LatchBio、OMERO、Protocols.io、Open Notebook、Ginkgo Cloud Lab、LabArchives 和 Opentrons 明确定义的技能。同样，智能体并不局限于这些平台：任何能从 Python 访问的 API 或平台都可以使用，这些技能只是经过优化、预先写好文档的路径
  • 30 多个分析与传播工具：文献综述、证据可追溯的科学写作、保密的同行评审、文档处理、Paperclip（全文论文、FDA/PMDA/EMA 申报文件和试验注册信息，引文可精确到行）、Paperzilla、Exa Search、不含宏的 PPTX 海报、幻灯片、示意图、信息图、Mermaid 图表等
  • 10 多个研究与临床工具：以证据为边界的假设生成、基金申请写作、汇总层面的临床决策支持研究、临床医生已作出的治疗计划的格式整理、PK/PD 建模与仿真（非房室分析、群体药代动力学、暴露-效应、生物等效性、首次人体给药剂量）、BIDS、ISO 标准就绪的证据准备（ISO 13485、ISO 14971、ISO/IEC 17025、ISO 15189）、分析方法验证与转移（ICH Q2(R2)/Q14、ICH M10、USP、CLSI EP）、情景分析，以及用 Autoskill 从工作流中起草技能

每个技能都有一个 SKILL.md，写明其用途、工作流和版本元数据。根据工作流的不同，还可能包含代码示例、参考文档、可执行的辅助脚本或模板。带有 scripts/ 的技能在 tests/<skill-name>/ 下有对应的测试套件，并在 tests/skill-requirements.toml 中有一条依赖项记录。

2.71.0 版本更新

这次更新刷新了全部 181 个技能，包括软件包和 API 指南、依赖要求、参考文档以及验证工作流。主要内容：

  • 数据库检索： Database Lookup 现在收录 80 个数据源，并写明访问要求、检索约定和来源核查。
  • 软件包兼容性： 更新后的文档基线包括 PathML 3.0.8、GeoPandas 1.2.0，以及用于实验室硬件 CAD 的 build123d 0.13.0。PufferLib 区分了原生 5.0、PyPI 上的 3.0.0 和历史版本 4.0 三种工作流。
  • 图像生成与智能体工具： Generate Image 使用 OpenRouter Image API，支持模型发现和请求验证。Pi Agent 记录了 Pi 0.99.2、原生 MCP 以及更新后的生态软件包。
  • RNA-seq 工作流的边界： Bulk RNA-seq 负责准备测序读段和经过验证的计数矩阵，再交给 PyDESeq2；下游的富集分析由 Pathway Enrichment 负责。

每个技能都记录了自己的兼容性要求和验证范围。重用较早的工作流之前，请先核对这些信息；本地测试、在线服务检查和示意性示例的覆盖范围各不相同。

🔬 使用场景

🧪 药物发现与药物化学

  • 虚拟筛选：针对蛋白质靶点，从 PubChem/ZINC 中筛选数百万种化合物
  • 先导化合物优化：用 RDKit 分析构效关系，用 datamol 生成类似物
  • ADMET 预测：用 DeepChem 预测吸收、分布、代谢、排泄和毒性
  • 分子对接：用 DiffDock 预测结合构象，并用面向亲和力的工具重新打分
  • 生物活性挖掘：在 ChEMBL 中查询已知抑制剂并分析构效关系模式

🧬 生物信息学与基因组学

  • 序列分析：用 BioPython 和 pysam 处理 DNA/RNA/蛋白质序列
  • 单细胞分析：用 Scanpy 分析 10X Genomics 数据、识别细胞类型，用 Arboreto 推断基因调控网络
  • 变异注释：用 Ensembl VEP 注释研究用 VCF 文件，并检索 ClinVar 证据，供有资质的人员解读
  • 变异数据库管理：用 TileDB-VCF 构建可扩展的 VCF 数据库，支持增量添加样本、高效的群体规模查询，以及基因组变异数据的压缩存储
  • 群体基因组学：用 OneKGPd 在 3,202 人的 GRCh38 千人基因组队列中查询变异、队列样本 ID 和亲缘关系
  • 调控序列模型：运行托管的 Genomic Intelligence 启动子、剪接、增强子、染色质、表达和基因注释预测，用于研究，而不是临床或诊断决策
  • 变异效应预测：查询任一 GRCh38 单核苷酸变异在 AlphaGenome Atlas 中的 AVI 分数、Phred 排名、特征归因和各组织轨道效应，或用 AlphaGenome 模型给变异打分并做计算机模拟突变，用于研究上的优先级排序，而不是诊断
  • 病原体监测：通过 GenSpectrum LAPIS API 追踪当前正在流行的病毒谱系及其增长速度（SARS-CoV-2、包括 H5N1 在内的流感、RSV、猴痘、麻疹、登革热），报告延迟是实测的而不是假设的
  • 基因发现：在 NCBI Gene、UniProt 和 Ensembl 中查询全面的基因信息
  • 网络分析：通过 STRING 识别蛋白质-蛋白质相互作用，并映射到通路（KEGG、Reactome）

🏥 临床研究与证据工作流

  • 临床试验：分析汇总层面的试验格局和方案入排标准，但不判断个人是否符合入组条件
  • 变异证据审查：用 ClinVar、COSMIC 和 ClinPGx 注释经授权的研究数据；解读责任仍由有资质的专业人员承担
  • 药物安全研究：在 FDA 数据库中查询汇总层面的不良事件、相互作用和召回证据
  • 临床药理学：从浓度-时间数据推导暴露指标，拟合房室模型和群体药代动力学模型，建立暴露与效应的关系，并评估给药方案、生物等效性和首次人体给药剂量
  • 全文证据检索：用 Paperclip 端到端地搜索和阅读论文、监管申报文件和试验记录，返回精确到行号而不是摘要的引文
  • 决策支持评估：准备合成数据或汇总数据层面的评估、证据概况、隐私和治理材料，而不是实时的临床决策
  • 临床医生撰写的文档：整理经核实、绑定数据来源的报告草稿，并对已获授权的执业专业人员已作出的治疗决定进行格式整理

🔬 多组学与系统生物学

  • 多组学整合：整合 RNA-seq、蛋白质组学和代谢组学数据
  • 通路分析：在 KEGG/Reactome 通路中对差异表达基因做富集分析
  • 网络生物学：重建基因调控网络，识别枢纽基因
  • 生物标志物发现：整合多组学层次来预测患者结局

📊 数据分析与可视化

  • 统计分析：进行假设检验、功效分析和实验设计
  • 出版级图表：用 matplotlib 和 seaborn 绘制出版质量的可视化图表
  • 网络可视化：用 NetworkX 可视化生物网络
  • 报告生成：用 Scientific Writing 和文档工具生成证据可追溯的研究报告；Clinical Reports 的输出始终是明确标注的草稿，只基于经核实的合成、去标识化或汇总的数据事实生成

🧪 实验室自动化

  • 方案设计：在经过培训的操作员审核之前，编写并模拟 Opentrons 或 PyLabRobot 实验方案
  • LIMS/ELN 集成：准备有明确范围的 Benchling 和 LabArchives 操作，远程写入需要明确授权
  • 工作流自动化：离线验证和模拟多步骤的实验室工作流；实际执行仍受设备特定的操作员安全关卡约束
  • 定制实验室硬件加工：先对 STEP 文件做预检，再在 Fictiv 上获取 CNC 加工或 3D 打印零件的报价，并把可制造性（DFM）反馈和交期选项转达给你；在你明确批准确切总价之前不会下任何订单

🐛 报告问题

如何贡献

  1. Fork 本仓库
  2. 创建一个功能分支（git checkout -b feature/amazing-skill）
  3. 遵循 CONTRIBUTING.md 和现有的目录结构
  4. 确保所有新技能都包含有效的 SKILL.md 文件，带有必需的 frontmatter 和 metadata.version
  5. 测试：充分测试你的示例和工作流；如果你的技能附带 scripts/，请在 tests/<skill-name>/ 下添加测试套件
  6. 提交你的更改（git commit -m 'Add amazing skill'）
  7. 推送到你的分支（git push origin feature/amazing-skill）
  8. 发起拉取请求，并清楚说明你做了哪些更改

贡献准则

✅ 遵循 Agent Skills 规范：每个技能都必须符合官方规范（有效的 SKILL.md frontmatter、命名约定、目录结构）
✅ 在每个 SKILL.md 中包含一个加了引号的 metadata.version 值
✅ 更新现有技能时递增 metadata.version
✅ 与现有技能的文档格式保持一致
✅ 确保所有代码示例都经过测试且能正常运行
✅ 在示例和工作流中遵循科学上的最佳实践
✅ 添加新功能时更新相关文档
✅ 在代码中提供清晰的注释和文档字符串
✅ 附上官方文档的参考链接

测试

每个附带 scripts/ 的技能都必须在 tests/<skill-name>/ 下有一个测试套件，并在 tests/skill-requirements.toml 中有一条记录。tests/_meta 守卫会检查这一覆盖情况以及共同的结构约定：frontmatter、文档长度、本地链接、脚本语法、字节码和硬编码的本地路径。它还会根据随附的 Agent Plugins 模式验证 plugin.json，并检查其版本与 pyproject.toml 一致。命令行 --help 检查和示例的执行检查属于各个技能自己的测试套件。

每个 pytest 进程只运行一个技能的测试：不同的技能会复用 _common 之类的模块名，一次收集多个测试套件可能会导入错误的模块。tests/run_all.py 负责进程隔离；--isolated 还会为每个技能提供其声明的依赖环境。在当前环境中运行某个测试套件时，如果缺少所需的软件包，部分检查可能会被跳过。

Skill Tests 工作流会针对相关的拉取请求和推送到 main 的提交，运行结构约定检查和只依赖标准库的测试套件，也可以手动触发。完整的科学依赖测试不在 CI 中运行；请在发布之前或修改共同约定时运行它。有些技能需要外部运行时或系统工具；安装上的缺口记录在 tests/skill-requirements.toml 中。

🔧 故障排除

常见故障

问题：技能没有加载

  • 确认技能文件夹位于正确的目录（参见快速上手）
  • 每个技能文件夹中都必须有一个 SKILL.md 文件
  • 复制技能后重启你的智能体或 IDE
  • 在 Cursor 中，到 Settings → Rules 确认技能已被发现

问题：缺少 Python 依赖

  • 解决办法：查看相应的 SKILL.md 文件，了解所需的软件包
  • 安装依赖：uv pip install package-name

问题：API 速率限制

  • 解决办法：很多数据库都有速率限制，请查阅相应数据库的文档
  • 考虑使用缓存或批量请求

问题：身份验证错误

  • 解决办法：有些服务需要 API 密钥，请查看 SKILL.md 中的身份验证设置
  • 核实你的凭据和权限

问题：示例已过时

  • 解决办法：通过 GitHub Issues 报告该问题
  • 查阅软件包的官方文档，了解更新后的语法

问题：gh skill install 或文档中指向 scientific-skills/ 的链接失效（v2.43.0 及以后）

  • 从 v2.43.0 起，技能位于 skills/（而不是 scientific-skills/）下，以符合 GitHub CLI 所期望的 Agent Skills 目录结构
  • 把手动复制的路径、书签和引用中的 scientific-skills/<name> 更新为 skills/<name>
  • 拉取最新版本后，重新运行 gh skill install K-Dense-AI/scientific-agent-skills

答：仓库本身采用 MIT 许可证，允许商业使用。但是，各个技能可能采用不同的许可证，请查看每个技能 SKILL.md 文件中的 license 字段，确保符合你的预期用途。

问：所有技能的许可证都一样吗？
答：不一样。每个技能都在其 SKILL.md 文件的 license 元数据字段中写明了自己的许可证，这些许可证可能与仓库的 MIT 许可证不同。用户有责任查看并遵守自己所用每个技能的许可条款。

问：多久更新一次？
答：我们会定期更新技能，以跟上软件包和 API 的最新版本。重大更新会在发布说明中公布。

问：可以和其他 AI 模型一起使用吗？
答：核心的 SKILL.md 格式遵循开放的 Agent Skills 标准。安装路径、发现机制和对可选元数据的支持因宿主和版本而异，请查阅目标宿主的最新文档确认。
